## 候选沉淀点

### 1. 渲染开关字段需「渲染/初始化/提交」三处同步过滤（推荐，state/api domain）

**现象**：为 definitions 新增 `isDisplay` 渲染开关，若只在渲染层（ParamGrid/ParamCard）过滤，`initGroupValues`/`handleOk` 仍会初始化/提交隐藏字段，造成「不显示但提交」的数据不一致。

**解法**：统一 `isDisplay !== false` 判定（缺失/`true` 均渲染，兼容后端渐进式上线），并在渲染、初始化、提交三处同步过滤：

```ts
// 渲染层
const defs = (group.definitions ?? []).filter((d) => d.isDisplay !== false);
// 初始化层
for (const def of group.definitions ?? []) {
  if (def.isDisplay === false) continue;
  groupVal[def.code] = ...;
}
// 提交层
for (const def of group.definitions) {
  if (def.isDisplay === false) continue;
  paramValues[def.code] = ...;
}
```

**关键坑位**：
1. 判定用 `!== false` 而非 `=== true`——后端渐进式上线时缺失字段默认渲染
2. 表格类参数（库存/区域）行级数据来自 paramValues 而非 definitions 渲染开关，isDisplay 不适用于行级过滤
3. 改共享类型前 grep 全部消费者，确认每处是否需要同步过滤

## 推荐理由

「UI 显示开关字段需要渲染/初始化/提交三处一致性」是可复用模式，本仓库场景配置与版本管理两处均需遵守。
