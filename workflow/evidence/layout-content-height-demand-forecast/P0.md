# P0 — 改前准备

- gateReady: YES

## Scope

### 改什么

需求预测下 **预测结果** 和 **版本管理** 两个页面，把 flex-grow 高度链打破，改为内容撑开高度 + 页面级滚动。

### 涉及文件（5 个）

| # | 文件 | 改动 |
|:---|:---|:---|
| 1 | `.../demand-forecast/forecast-results/index.vue` | `.page-shell__body` 去掉 `flex: 1` |
| 2 | `.../demand-forecast/version-management/index.vue` | `.page-shell__body` 去掉 `flex: 1` |
| 3 | `.../forecast-results/components/tab-container/index.vue` | `.tab-shell` 去掉 `height:100%`; `.tab-content`/`.tab-scroll`/`.predict-content` 去掉 `flex:1`+`overflow-y:auto`+`min-height:0`; `.tab-shell .tab-content` 的 flex |
| 4 | `.../forecast-results/.../version-info.vue` | `.version-info` 去掉 `flex: 1 1 auto` + `overflow: auto` |
| 5 | `.../version-management/.../version-table/index.vue` | `.table-card` 去掉 `height:100%`; `.table-card__body` 去掉 `flex:1` |

### 不改

- 页面根容器（`.demand-forecast-*-page`）保留 `flex: 1 1 auto` + `height: 100%`（页面仍需占满视口）
- `.page-shell` 保留 `height: 100%` + `overflow: auto`（唯一的页面级滚动容器）
- 其他模块（产能分配、订单分级等）不做同样改动

## Risks

1. **微应用高度问题**：EmbedMicroApp 子应用可能依赖父级 `flex: 1` 来计算内部高度。对策：移除高度约束后子应用应以内容自然高度渲染，如有异常需在子应用侧修复。
2. **表格内部分页区域**：version-management 的表格使用 `CommonAntvTable` 的 `scroll.y` 来控制表格滚动。移除 `flex: 1` 后表格外层不再有固定高度，`scroll.y` 可能需要调整或去掉。
