# P0 — stocking-constraints-autofill

## Scope

**涉及文件：**
- `apps/main-app/src/api/capacity-allocation/version.ts` — AllocationVersionConstraintsData 类型新增 cnNbr/cnPvc/idnNbr/idnPvc/vnNbr/vnPvc
- `apps/main-app/src/views/capacity-allocation/version-management/components/CreateVersionModal/composables/useCreateVersionModal.ts` — applyConstraints 内回填 stockingValues

**非目标（明确不做）：**
- 不改 ParamGrid.vue / index.vue（UI 层不动）
- 不改 watchConstraints 触发时机（仍监听 FORECAST_DATA.FORECAST_VERSION）
- 不改 onScenarioChange 的场景回填逻辑
- 不改 constraints 接口路径与请求方式

## Risks

1. **字段映射错位**：接口 camelCase（cnNbr）与前端 flat key（CN_NBR）转换若写反前后缀（如 nbrCn）会静默取到 undefined — 缓解：由 STOCKING_LOCATIONS/STOCKING_PRODUCTS 常量统一生成映射，与提交组装同源。
2. **空值覆盖用户输入**：后端未返回新字段（旧版本接口）时，若直接赋值会把用户已填/场景回填的值覆盖为 undefined — 缓解：仅当字段值为有效 number 时才写入。
3. **回填时序冲突**：切换场景（onScenarioChange 回填）与切换预测版本（applyConstraints 回填）先后触发时，后者覆盖前者 — 与其他参数卡片（区域平衡等）现有行为一致，视为预期行为（预测版本约束优先）。
