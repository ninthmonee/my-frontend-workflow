## Risks

1. **warning 响应格式假设**：若后端返回的 `confirmMessages` 字段路径不是 `err.response.data.data.confirmMessages`（例如不同 http 库版本下 error 结构有差异），可能导致 confirmMessages 列表提取失败，用户看不到 warning 弹窗而直接报错。缓解：在提取 `confirmMessages` 时做多层 fallback（`err?.data?.data?.confirmMessages || err?.data?.data?.confirmMessages`）。

2. **嵌套 modal 的 z-index 层级**：warning 弹窗在 CreateVersionModal 内部通过 `useModal` 唤起，两个 modal 同属一个 Vue app 上下文，antdv-next Modal 的 `zIndex` 默认为 1000，若嵌套层级过深可能导致遮挡问题。缓解：warning modal 设置合适的 `zIndex`（如 1100）确保覆盖在主弹窗上方。

3. **loading 状态竞争**：首次调用失败后 loading 已设为 false，用户点击「继续运行」后需重新设置 loading=true。若在此过程中用户快速点击主弹窗「运行算法」按钮，可能导致重复提交。缓解：`loading` ref 已在 composable 中统一管理，重试期间 loading 为 true 会禁用按钮。
