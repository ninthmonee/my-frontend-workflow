## 候选沉淀点

### 1. 共享类型 `paramValues` 放宽回归（推荐，api domain）

**现象**：`ScenarioDetail.groups[].paramValues` 从 `Record<string, number>` 放宽为 `Record<string, unknown>` 后，typecheck 报错：
`useCreateVersionModal.ts(302,7): Type '{ [x: string]: unknown; }' is not assignable to type 'Record<string, number | null>'`

**根因**：`useCreateVersionModal.loadScenarioDetail` 会把场景详情的 `paramValues` 展开进 `stockingValues`（类型 `Record<string, number | null>`）。放宽共享类型时未全局检索消费者，破坏索引签名兼容。

**解法**：共享 API 类型修改前 MUST `grep` 该类型的全部消费者；类型需保持最小放宽（本场景 `paramValues` 保持 `Record<string, number>`，动态渲染数据源用新增的 `definitions` 字段，不改旧字段契约）。

**验证**：typecheck + build 全绿。

### 2. 需求中途变更 → 组件复用收敛（Ponytail）

**现象**：按初稿新增 `RegionalBalanceCard`（三列表格），用户 Phase 3 确认时改为「不显示表格，name+description」。
**处理**：删除表格组件（与 ParamCard 渲染完全重复），REGIONAL_BALANCE 统一走 ParamCard。符合 Ponytail 第 ① 级（YAGNI）与 ⑤ 级（项目内已有封装）。

## 推荐理由

候选 1 是典型「共享类型契约放宽导致消费者类型回归」的高复用坑（api 领域），且与本仓库 `useCreateVersionModal` 强相关；候选 2 属于需求澄清场景，价值较低。
