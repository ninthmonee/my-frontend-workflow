# P0 Evidence — remove-page-max-width-1440

## Scope

**涉及文件（10 个页面入口的 `.page-shell` 样式）：**
- apps/main-app/src/views/capacity-allocation/allocation-results/index.vue
- apps/main-app/src/views/capacity-allocation/scenario-config/index.vue
- apps/main-app/src/views/capacity-allocation/version-management/index.vue
- apps/main-app/src/views/demand-forecast/forecast-results/index.vue
- apps/main-app/src/views/demand-forecast/version-management/index.vue
- apps/main-app/src/views/master-data/supply-network/index.vue
- apps/main-app/src/views/order-grading/customer/index.vue
- apps/main-app/src/views/order-grading/product/index.vue
- apps/main-app/src/views/tracking-monitoring/target-monitoring/index.vue
- apps/main-app/src/views/tracking-monitoring/warning-management/index.vue

**删除内容（每文件 2 行）：**
- `.page-shell` 中 `max-width: 1440px;`
- `.page-shell` 中 `margin: 0 auto;`（配合 max-width 的居中设置，删除 max-width 后无意义）

**非目标（明确不做）：**
- 不改 `.page-shell` 的 flex 链 / height / overflow / padding 等其他属性
- 不改组件级（header-bar / tab-container / control-bar / table / modal）样式
- 不改响应式断点（@media max-width: 1200px 等媒体查询）
- 不动非业务页面（home / micro-app / _core 登录错误页——本身无 max-width）

## Risks

1. **误删风险**：10 个文件 `.page-shell` 块属性顺序/注释可能不完全一致，需逐文件确认目标行上下文后再删除，避免误删其他属性（如 height/overflow）。
2. **超宽屏回归**：删除后 >1440px 屏内容全宽拉伸，表格/图表/筛选栏可能过宽或间距失衡；无测试基础设施，需人工浏览器验证。
3. **经验库矛盾**：compound-engineering css.md「页面骨架」条目沉淀了 `max-width: 1440px` 模式，本次删除与之直接矛盾，Phase 4 必须更新/标注该条目（不改视为风险残留）。
