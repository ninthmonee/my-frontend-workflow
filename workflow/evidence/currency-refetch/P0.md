# P0 — 切换币种后自动重新请求当前页面数据

Change: `currency-refetch`
Mode: full

## 背景（用户已确认）

切换币种时选择「重新请求对应页面接口」（非刷新页面）。当前实现切换仅更新 store/header，已加载页面数据不自动刷新——需给三个页面编排补监听逻辑。

## Scope

### 涉及文件

- `apps/main-app/src/views/order-grading/customer/useCustomerOrchestration.ts`
  - init 记录「上次请求币种」；watch `currentCurrency.code` → 变化时复用 `onFilterChangeImmediate()` 刷新（退出编辑态 + 全量数据刷新 + 保留筛选/版本）
- `apps/main-app/src/views/order-grading/product/useProductOrchestration.ts`
  - 同上（复用其 `onFilterChangeImmediate()`）
- `apps/main-app/src/views/master-data/supply-network/useSupplyNetworkOrchestration.ts`
  - 同上；watch → 若编辑态先 `exitEdit()`，否则 `refreshTotalPaths()` + `search()`（参照现有版本切换 watch 模式）

### 非目标（明确不做）

- 不做币种持久化（localStorage）——用户选择仅「重新请求」，未选持久化
- 不改 header/组件/金额格式化（上一工作流已完成）
- 不做「全站刷新所有历史页面」——只刷新当前激活页面
- 不改接口定义与 X-Currency 注入（已生效）

## Risks

1. **首次加载竞态**：币种 `null → 首个币种` 的初始化赋值会触发 watch，此时页面数据可能已按默认币种请求过——需用「上次请求币种」ref 区分：init 时记录当前币种，watch 仅当 code 与上次记录不同才刷新（避免进入页面时重复请求）
2. **编辑态丢失**：客户/产品复用 `onFilterChangeImmediate` 会退出表格编辑态（未保存的人工调整丢失）；供应网络编辑态需先 `exitEdit()`。币种切换语义上等同数据源变化，与版本切换行为一致，可接受——在交付说明中提示用户
3. **刷新函数副作用**：`onFilterChangeImmediate` 会清空选中行/趋势图/页码——币种切换触发同样行为，与筛选/版本切换一致，符合「数据源变化」语义
4. **watch 初始触发**：需 `{ flush }` 或条件判断避免 watch 在初始化阶段立即执行；统一在 watch 回调内比较上次币种
