# P0 — 改前准备

## Scope

### 涉及文件

| 文件 | 改动 |
|------|------|
| `apps/main-app/src/router/guard.ts` | setupAccessGuard 中：① generateAccess 后检测空菜单 → 跳 /403；② fetchUserInfo 外增 try-catch 兜底 |
| `packages/effects/layouts/src/basic/layout.vue` | 侧边栏 #menu 插槽中检测 sidebarMenus 为空时渲染「无权限」提示，RouterView 区域渲染 403 Fallback 组件 |

### 非目标（不做）

- 不修改 core.ts 的 403 路由
- 不修改 forbidden.vue 本身
- 不改变 OAuth2 登录流程
- 不新增路由或 store 字段

## Risks

1. **风险**：guard 中 fetchUserInfo try-catch 后跳 /403，可能掩盖了真实的 API 网络错误（用户并非无权限而是服务挂了），建议在 catch 中区分 401/403 vs 其他网络错误。
2. **风险**：layout 中检测空菜单的时机——sidebarMenus 可能在初始渲染时尚未计算完成，需用 `isAccessChecked` 门控，避免短暂的空白闪烁被误判为"无权限"。
3. **风险**：`packages/effects/layouts` 是共享包，修改可能影响其他使用该 layout 的应用。需确认仅 main-app 使用 BasicLayout。

## 根因分析

1. guard.ts 第 105 行 `await authStore.fetchUserInfo()` 无 try-catch，API 异常时 beforeEach 静默失败 → 白屏
2. guard.ts 第 112-153 行 generateAccess 返回空菜单后，`homeAccessMenu` 为 undefined，redirect 到 `/home`（defaultHomePath）→ 匹配 `/:path(.*)*` fallback → 用户看到 404 而非 403，不知道是权限问题
