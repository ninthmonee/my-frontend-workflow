# P0 — 改前准备（region-tag-color-pool）

## Scope

**涉及文件（修改）：**
1. `apps/main-app/src/store/enum.ts`
   - 删除 `ENUM_FALLBACK_MAP` 中 `CustomerRegion` 条目（写死 5 大区：内销/欧洲/北美/亚太/日韩）
   - 删除 `TAG_COLOR_MAP`（写死 6 个大区颜色映射）
   - 新增固定 50 色数组 `CUSTOMER_REGION_TAG_COLORS`
   - `fetchCustomerRegionOptions` 按返回顺序 `index % 50` 绑定 `tagColor`
2. `apps/main-app/src/views/tracking-monitoring/warning-management/components/TargetDeviationTab.vue`
   - `tagColorMap.saleZone` 写死 5 大区颜色 → 改走 `enumStore.getCustomerRegionTagColor(v)`
3. `apps/main-app/src/views/tracking-monitoring/warning-management/components/ThresholdConfigTab.vue`
   - 同上

**非目标（明确不做）：**
- 不改 `DimensionEditModal` 大区数据源（保持 `getSafeEnumOptions` 读 meta-data 注册表；enum 大区数据初始化即加载）
- 保留 `StrategicLevel` / `ProductLevel` 的 `ENUM_FALLBACK_MAP` 兜底（非大区）
- 保留 `customerLevel` / `productLevel` 的 `tagColorMap` 颜色（非大区）
- 不改客户分级/需求预测/供应网络等通过 `getCustomerRegionOptions()` 取大区的页面（自动受益于新颜色绑定）

## Risks

1. **DimensionEditModal 大区下拉空态风险（中）**：移除 `CustomerRegion` 兜底后，`getSafeEnumOptions(CustomerRegion)` 仅返回 meta-data 注册表数据；若后端注册表不返回该枚举，大区下拉为空。缓解：用户已确认 enum 大区数据初始化即加载（sale-zone 接口），且注册表含 CustomerRegion 时正常。
2. **预警管理 saleZone Tag 颜色匹配风险（低）**：`getCustomerRegionTagColor` 用 `dimJson.saleZone` 值与 `customerRegionList` 的 `value`（code）精确匹配；若两者格式不一致（空格/大小写/编码），返回 `default` 灰色。现有写死 map 用中文 key 直接匹配，行为接近，风险低。
3. **50 色循环取色（低）**：大区数量 >50 时 `index % 50` 循环，第 51 个大区与第 1 个大区同色；实际场景大区数量远小于 50，可接受。
