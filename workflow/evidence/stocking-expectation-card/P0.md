# P0 — stocking-expectation-card

## Scope

**涉及文件：**
- `apps/main-app/src/views/capacity-allocation/version-management/components/CreateVersionModal/ParamGrid.vue` — 新增 stockingValues prop、期望库存水位表格分支（ATable + InputNumber）
- `apps/main-app/src/views/capacity-allocation/version-management/components/CreateVersionModal/index.vue` — 解构并透传 stockingValues

**非目标（明确不做）：**
- 不改 `useCreateVersionModal.ts`（stockingValues 状态/回填/提交组装已存在且符合目标 JSON 结构）
- 不改 `version-management/constants.ts`（STOCKING_LOCATIONS/STOCKING_PRODUCTS/CREATE_PARAM_GROUPS 已定义）
- 不改场景配置页（scenario-config）及后端 API 层
- 不调整其他参数卡片的布局/样式

## Risks

1. **params-grid 布局挤压**：现有 grid 为 `1fr 1fr 1fr 2fr` 四列，STOCKING_EXPECTATION 是第 5 个 item 会换行到第二行首列（1fr 宽），三列表格在窄列内可能拥挤 — 缓解：列宽参考 REGIONAL_BALANCE 的紧凑写法（54/78/78），InputNumber 100% 宽。
2. **禁用态遗漏**：场景未启用该组时 InputNumber 必须 disabled，否则用户输入的值不会随 enabled=false 生效预期 — 缓解：每个 InputNumber 绑定 `:disabled="!isGroupEnabled('STOCKING_EXPECTATION')"`，与 REGIONAL_BALANCE 一致。
3. **key 拼写不一致**：行/列 key 拼接必须为 `${loc}_${prod}`（如 CN_NBR），若写反（NBR_CN）提交 paramValues 将与后端契约不符 — 缓解：复用 constants 的 STOCKING_LOCATIONS/STOCKING_PRODUCTS，与 useCreateVersionModal 的 initStockingValues 相同拼接顺序。
