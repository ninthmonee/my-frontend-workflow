## Risks

1. **hooks.json 格式风险**：Reasonix hooks 配置格式基于二进制逆向推断（`reasonix/internal/hook` 包中的 `GlobalSettingsPath`/`ProjectSettingsPath`/`ResolvedHook`/`MatchesTool`），实际 Reasonix 可能使用不同 schema。**缓解**：首次部署后需验证 `/hooks trust` 和 hook 触发是否生效。

2. **PreToolUse 阻断误伤**：非 DevFlow 的常规对话中编辑文件可能被误阻断。**缓解**：gate-guard.js 在 `state.json` 不存在或 `taskType` 为 `auto-skip`/`user-skip` 时直接放行。

3. **SessionStart 上下文膨胀**：注入内容过多会浪费 context budget。**缓解**：注入文本控制在 300 字以内，仅包含状态摘要 + 3 条核心约束。

4. **Node.js 脚本性能**：PreToolUse 在每次工具调用前都会 fork 进程。**缓解**：脚本逻辑极简（单文件 < 80 行），纯同步 fs 操作，无外部依赖，target < 50ms 执行时间。

5. **项目信任机制**：`.reasonix/hooks.json` 首次部署后需要用户手动执行 `/hooks trust`，否则 hooks 不生效。**缓解**：部署后在 AGENTS.md 或 session 中明确提示。
