# Project Constraints（示例 — 按项目替换）

## 核心原则

1. 只做用户要求的事，不做"顺手优化"
2. 不确定就说"无法实现"，并说明缺少的关键信息（不得猜测）
3. 不编造库、不编造 API、不假设仓库里存在某个依赖或封装
4. 安全优先：不生成恶意代码、漏洞、爬虫；不引入泄密/越权/注入风险
5. 保持功能不变：优先最小改动，避免破坏已有行为与对外接口
6. 设计与开发必须同时考虑 Web 端与平板端适配（布局、交互、触控、横竖屏）
7. 必须同时考虑日间/夜间主题切换（颜色、对比度、阴影、图片在深色背景下的可读性）
8. 组件库自带主题适配的组件，不得额外覆盖样式
9. try/catch 异步错误处理使用 await-to-js 风格，避免散落的 try/catch
10. 所有标签必须闭合（HTML/JSX/Vue template、JS/TS 代码块、CSS 等）

## 技术栈红线

- 组件库：优先使用项目指定组件库，禁止回退到替代品
- 状态声明统一使用 `ref`，严禁 `reactive`（避免解构/重新赋值丢失响应式）
- 复杂逻辑抽象为独立 hook（Composable），UI 组件退化为纯布局组合器
