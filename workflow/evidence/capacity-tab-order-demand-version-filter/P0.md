# P0 — 改前准备证据

## Scope
- **涉及文件（单文件）**：`apps/main-app/src/views/capacity-allocation/allocation-results/components/tab-container/index.vue`
- **变更内容**：
  1. `items` 数组重排：需求满足 tab 从第 2 位移至利润参考之后（新顺序：产能分配结果 → 销售目标 → 利润参考 → 需求满足 → 内销库存计划 → 多版本对比 → 基础信息）
  2. 需求满足 tab 筛选栏新增「预测版本」多选筛选项，数据来源：`listDemandForecastForecastResultVersionsApi({ year: props.decisionYear })`（需求预测-预测结果版本接口，选项映射 `{ value: id, label: versionName }`）
  3. 「预测版本」选中值传给子应用 `params.version_ids`（未选择时回退 `[props.versionId]`）
- **非目标（不做）**：
  - 不新增「产能分配版本」（request_ids）筛选项（用户已确认移除）
  - 不改动其他 tab（分配结果/销售目标/利润参考/内销库存计划/多版本对比/基础信息）的顺序与筛选
  - 不修改 `request_ids` 传参逻辑（保持 `[props.requestNum]`）
  - 不改动接口定义、不改动其他模块

## Risks
- **R1（接口参数假设）**：`listDemandForecastForecastResultVersionsApi` 传 `{ year: decisionYear }`（'YYYY'）。预测结果页面用 `{ month }` 调用；若后端对 `year` 参数不识别或语义不同，预测版本选项可能为空。→ 缓解：接口错误/空数据时选项为空数组，不影响其他功能；TypeScript 层面接口签名接受 `year`。
- **R2（子应用兼容）**：`version_ids` 从固定 `[props.versionId]` 变为可选数组。若子应用 demand-fulfillment 对空数组或意外值处理不当可能显示异常。→ 缓解：未选择时回退原默认值 `[props.versionId]`，行为向后兼容。
- **R3（Tab 顺序变更）**：重排后默认激活 tab 不变（version-info 是初始 activeKey，且 template 用 v-if 按 key 渲染，不依赖顺序）。subAppHeight 的 switch 按 key 匹配，与顺序无关。→ 风险低。
