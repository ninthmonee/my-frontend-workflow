## Risks

1. **大规模类型变更导致组件编译错误**：`types.ts` 重写后所有引用旧类型的组件（10 个文件）都会报错，需要逐一适配。若遗漏任何字段引用会导致 typecheck 失败。
2. **API 响应结构未验证**：接口文档仅描述预期格式，实际后端返回可能与文档不完全一致（如 status 枚举值、字段缺失等）。需做好空值兜底。
3. **ReceiverTags 组件依赖变化**：`receivers` 从 `string[]` 变为 `SendToItem[]` 后，该组件为通用组件，需确认是否有其他调用方使用。若有则不能直接修改签名。
4. **Tab 切换时的数据一致性**：选择"一次性全量加载"，需确保 3 个 API 全部完成后才渲染，避免 tab 切换时数据不完整。
