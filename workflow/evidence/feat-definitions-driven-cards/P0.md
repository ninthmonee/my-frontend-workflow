# P0 — feat-definitions-driven-cards

## Scope

### 涉及文件 / 目录
| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `apps/main-app/src/api/capacity-allocation/scenario.ts` | 修改 | 新增 `ScenarioParamDefinition` 类型；`ScenarioDetail.groups` 增加 `definitions` 字段 |
| `apps/main-app/src/views/capacity-allocation/scenario-config/composables/useScenarioConfig.ts` | 修改 | 存储完整 `scenarioDetail`，暴露给 UI 层；保留所有 enabled/editing/toggleGroup 逻辑 |
| `apps/main-app/src/views/capacity-allocation/scenario-config/index.vue` | 修改 | 从 API 数据传 definitions → 卡片，替代硬编码 `SCENARIO_PARAM_GROUPS` |
| `apps/main-app/src/views/capacity-allocation/scenario-config/components/ParamCard.vue` | 修改 | props 改为 `definitions` + `groupName`，渲染 definitions[].name + description |
| `apps/main-app/src/views/capacity-allocation/scenario-config/components/InventoryLevelCard.vue` | 修改 | props 改为 `definitions` + `groupName`，表格单元格数据来自 definitions |
| `apps/main-app/src/views/capacity-allocation/scenario-config/constants.ts` | 修改 | 移除不再使用的 `SCENARIO_PARAM_GROUPS`，保留 `STOCKING_LOCATIONS`/`STOCKING_PRODUCTS`/`SCENARIO_GROUP_CODES` |

### 非目标（明确不做）
- 不改 `allocation-results`、`version-management` 相关组件
- 不改 `CreateVersionModal`、`CreateScenarioModal`
- 不改变场景创建/删除/编辑保存的业务逻辑
- 不改变编辑模式下的交互行为（复选框勾选、保存/取消）
- 不改变 `ScenarioItem`（场景列表项）类型
- 不改变 CSS 样式

## Risks

### R1: `ScenarioDetail.groups` 类型变更影响其他使用方
- **严重度**: low
- **缓解**: `ScenarioDetail` 仅在 `useScenarioConfig.ts` 中使用（经 codegraph 验证无其他调用方），blast radius 可控

### R2: `STOCKING_EXPECTATION` 表格布局映射
- **严重度**: medium
- **说明**: definitions 的 code 命名（如 `CN_PVC`、`VN_NBR`）需要解析为 location（CN/VN/IDN）和 product（NBR/PVC），以维持现有的 3×2 表格布局
- **缓解**: 保留 `STOCKING_LOCATIONS`/`STOCKING_PRODUCTS` 常量作为布局结构，从 definitions 中按 code 查找对应的 displayValue/description

### R3: 首次加载/数据为空时 cards 无内容
- **严重度**: low
- **说明**: 切换场景时 API 可能未返回 definitions（如网络错误），卡片需有兜底空态
- **缓解**: ParamCard 和 InventoryLevelCard 的 v-for 渲染空数组时自然为空（只显示标题行），不会崩溃
